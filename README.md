# ДЗ 1. Анализ временного ряда продаж

Выбранный товар: **47566 — PARTY BUNTING**, гирлянды из флажков.
Период: 01.12.2010–09.12.2011. Весь код, графики и выводы находятся
в [hw_1.ipynb](hw_1.ipynb). Расчёты и графики оформлены в функции.

## Данные

Источник — [UCI Online Retail](https://archive.ics.uci.edu/dataset/352/online+retail),
лицензия CC BY 4.0. Notebook сначала загружает архив из интернета,
а при ошибке использует `data/raw/online+retail.zip`. Архив не включён в Git.

Показатель — количество проданных единиц по всем странам: положительные
`Quantity`, счета без префикса C. Возвраты не вычитаются из продаж.
Ряд построен по дням, неделям и месяцам.

## Запуск

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install notebook ipykernel numpy pandas openpyxl matplotlib "statsmodels>=0.15"
python -m ipykernel install --prefix .venv --name hw1-retail --display-name "Python (hw1-retail)"
jupyter notebook hw_1.ipynb
```

Выбрать ядро **Python (hw1-retail)** и выполнить **Restart Kernel and Run All Cells**.
Notebook проверен последовательным запуском с чистого ядра на Python 3.14.

## Основные выводы

- В датах и количествах пропусков нет. В 80 днях покупок товара не было,
  поэтому они заполнены нулями: считаем журнал транзакций полным.
- По IQR найдено 27 потенциальных выбросов. Я их оставил: проверенные пики
  складываются из крупных оптовых заказов, а не выглядят ошибками ввода.
- Средние продажи — 48.9 штуки в день, медиана — 21.5. Есть весенне-летний
  подъём: 486 штук в январе, 3565 в мае и 620 в октябре.
  Недельная и месячная агрегации сглаживают дневные колебания.
- STL и ACF показывают недельный ритм. Продажи обычно выше во вторник
  и четверг, минимум — в субботу. Для подтверждения годовой сезонности
  одного года истории недостаточно.
- Исходный ряд не проходит проверку стационарности. После `log1p` и разности
  с лагом 7 ADF и KPSS поддерживают стационарность уровня. Разброс по времени
  всё ещё меняется, поэтому полную стационарность не утверждаю.
